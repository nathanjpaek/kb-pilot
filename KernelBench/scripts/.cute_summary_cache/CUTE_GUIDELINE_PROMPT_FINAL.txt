──────────────────────────────────────── CuTe DSL Quick-Reference Guideline ────────────────────────────────
Purpose: Equip an LLM (or human) with the minimal yet sufficient rules to emit syntactically-correct, performance-portable CuTe DSL kernels on first try.  (<≈2 300 words)

1. CORE CONCEPTS  
• Tensor = (ptr, layout, meta).  “ptr” is a device pointer, “layout” is a compile-time object mapping logical indices → linear memory, “meta” holds dtype, rank, strides, space (gmem/smem/reg).  
• Layout Algebra: compose with cute.row_major(shape…), cute.col_major(...), cute.tile(lhs, rhs), cute.swizzle(bank), cute.pad(shape, pad), etc.  Compile-time constant shapes yield static layouts; runtime ints yield dynamic layouts.  Keep ranks ≤ 8.  
• Memory Spaces: registers (implicit), __shared__ (static bytes or cute.shared_array(dtype, n)), L2, global.  Prefer REG→(SMEM)→GMEM movement.  
• Data Types: uint{8,16,32}, int{8,16,32}, fp16, bf16, fp32, fp8_e4m3/e5m2 (Hopper+).  Always annotate kernel args & locals: T: cute.float16.  For Tensor Cores, use fp16/bf16 for inputs, fp32 for accum; fp8 requires explicit scale.  
• Compile-time Const: wrap with cute.const_expr(x) or decorate func with preprocessor=True so “if const_expr(idx==0): …” branches vanish.  Never feed runtime values to const_expr.  
• Calling convention: scalars pass by value; tensors pass (ptr, layout) pairs; compile-time ints/enums pass as template parameters via cute.static_argnames([…]).  Inlining is automatic, recursion forbidden.

2. KERNEL STRUCTURE & DECORATORS  
• Host controller:  
  @cute.jit                                  # jit-compile Python → GPU launcher  
  def gemm(A: torch.Tensor, B: torch.Tensor):  
      grid = ( (A.shape[0]+TM-1)//TM, (B.shape[1]+TN-1)//TN )  
      block = (cute.cute_warp_size, 1, 1)      # ≤1024 threads /block  
      _gemm_kernel.launch(grid, block)(A_dlpack, B_dlpack, …)  
• Device kernel:  
  @cute.kernel                                # emitted as __global__  
  def _gemm_kernel(a_ptr, b_ptr, c_ptr, M:int, N:int, K:int):  
      tid = cute.thread_rank()                # 0-based linear tid in block  
      # … body …  
• Always call .launch(grid, block)(args); forgetting fails silently.  
• Grid-stride loop idiom for variable M,N:  
  for m in cute.grid_range(tid, gridDim.x*blockDim.x, M): …  
• Use cute.barrier() or cute.syncthreads() for full-block sync; conditional sync is UB.  
• Format restrictions inside @kernel:  no Python classes, yield/await, list/dict comp, dynamic recursion, arbitrary globals.  Only simple for/while with static bounds or grid_range tracing; imports limited to cute.*, math, typing.  
• Prefer preprocessor (preprocessor=True argument or env CUTLASS_DSL_PREPROCESS=1) for complex kernels → robust AST rewrite.

3. MEMORY OPERATIONS  
• Copy atom: cute.copy(dst_tensor, src_tensor, vec=Vec, async_cp=True)  
  – vec must evenly divide contiguous dimension bytes; align mod 16 for L2, 32 for GMEM->SMEM.  
  – async_cp requires cp.async (Ampere) or TMA (Hopper); pair with cute.commit_group() and cute.wait_group(stage).  
• MMA atom: cute.mma(acc, A_frag, B_frag, mma_layout="m16n8k16", accumulate=True)  
  – A_frag/B_frag from shared memory; load with cute.partition(A_smem, …).  
  – Split-K: accumulate partial acc in registers, then cute.reduce_partial(acc, k_parts) before global store.  
• Store: cute.copy(gmem_C, smem_C, vec=Vec, async_cp=False) after sync to ensure commits finished.  
• Pointer arithmetic: use cute.scalar_ptr(ptr, offset) not ptr+offset to keep SSA trace.  
• Avoid allocating tensors inside kernels; allocate outside and pass pointers.

4. THREAD-VALUE LAYOUTS & TILING  
• Map computation hierarchy (block, warp, thread, lane) to problem tiles via cute.partition():  
  block_tile = cute.tile((TM,TN),(BK,BK))          # logical tile dims  
  warp_tile  = cute.tile(block_tile, (WM,WN))      # subdivide for each warp  
  thread_tile= cute.tile(warp_tile, (TMMA,NMMA))   # per-lane MMA gemm  
• Partition example:  
  A_smem = cute.make_tensor(a_shared_ptr, block_A_layout)  
  A_warp = cute.partition(A_smem, warp_idx, warp_layout)  
• Maintain even divisibility else strided remainder path needed (slow).  
• Thread layout win: ensure consecutive threads access consecutive addresses → coalesced; bank-align SMEM rows (pad to 32b).  
• Double buffering: allocate 2× SMEM tiles; stage = cute.thread_rank(0) &1; cp.async to buffer[stage^1]; compute on buffer[stage]; toggle; syncthreads/smwait.  
• Autotune TM,TN,BK via cute.autotune(grid, search_space) or external script.

5. CRITICAL PATTERNS & IDIOMS  
• GMEM→SMEM→REG Canonical GEMM Skeleton  
  for k0 in range(0,K, BK):  
      prefetch A/B tile with cp.async;  
      cute.syncthreads();  
      for kk in range(0,BK, TMMA_K):  
          A_frag = cute.load_gemm_A(smem_A, kk);  
          B_frag = cute.load_gemm_B(smem_B, kk);  
          cute.mma(acc, A_frag, B_frag);  
• Grid-Stride Map-Reduce:  
  sum = 0  
  for i in cute.grid_range(tid, nThreads*gridDim.x, N):  
      sum += x[i]  
  cute.block_reduce(sum, op="+")  
  if tid==0: cute.atomic_add(dst, sum)  
• Compile-time specialization:  
  @cute.kernel(preprocessor=True, specialize_args=["TM","TN"])  
  def k(TM:int, TN:int, ptr): …        # static TM,TN yield loop unrolling  
• DLPack integration:  
  torch_tensor = torch.randn(..., device="cuda")  
  cute_tensor  = cute.from_dlpack(torch_tensor)     # zero-copy  
• Software pipelining macro:  
  for stage in cute.range(prefetch_stages):  
      cute.cp_async_staged(buf[stage], gmem_ptr+stage*stride)  
      cute.commit_group()  
      cute.wait_group(stage)  
      compute(buf[stage])  
      cute.syncthreads()

6. COMMON MISTAKES TO AVOID  
• Declaring @cute.kernel on host wrapper; should be @cute.jit.  
• Forgetting .launch → function runs on CPU and silently allocates no GPU work.  
• Mismatching dtypes (e.g., fp16 inputs vs fp32 accum) without explicit cast.  
• Using Python int instead of cute.const_expr in compile-time branches.  
• Uncoalesced global accesses (strided by warp not lane).  
• Exceeding 48 KB SMEM (or 100 KB on Hopper) per block; kernel will launch but L2 spill thrashes.  
• Conditional syncthreads causing deadlock; barrier must execute by all threads or none.  
• Runtime allocation of tensors/register arrays inside kernel ➜ PTX stack spill.  
• Setting CUTLASS_* env vars after import—options locked at import.  
• Disabling JIT cache in production – recompiles kill latency.  
• Not scaling FP8 → accuracy loss; scale must be stored per-tensor or per-channel.  
• Over-specializing: many TM/TN variants explode compile time + binary size.

7. ARCHITECTURE-SPECIFIC CONSIDERATIONS  
Ampere (SM8x):  
  – cp.async supports 4-stage pipe; align 16 bytes; SMEM 96 KB split opt-in.  
  – Tensor Core mma.m16n8k16_fp16, mma.m8n8k4_int8.  
Hopper (SM90):  
  – Tensor Memory Accelerator (TMA): cute.tma_async(src, dst_layout); no L2 pollution.  
  – Tensor Core m16n16k16_fp8/bf16, m16n16k16_bf16, accumulator fp32.  
  – Shared memory up to 228 KB; prefer multi-stage (≥3) pipelining.  
  – WARPs: 32 threads but scheduler groups of 8; warp-specialize to reduce bank conflicts.  
Blackwell:  
  – Enhanced FP4/INT1 sparsity; ensure block-scaled formats with cute.block_scale(ptr, scale_ptr).  
General:  
  – Read true limits via cute.get_device_props(); clamp blockDim.x<=1024, blockDim.y*z <=64.  
  – Occupancy happy range 2-4 warps per SM; monitor register usage (max 255/ thread) via nvcc –Xptxas –v.  
  – Use cudaFuncSetAttribute(func, MaxDynamicSharedMemorySize, bytes) for >48 KB SMEM.  
  – fp8_e4m3 range narrower; pipeline accum to fp32 quickly.
